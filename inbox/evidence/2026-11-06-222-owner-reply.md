## النص الحرفي

> Thanks for tracing this. I checked the transition history: the removal was **not documented as an intentional overflow-policy decision**. PR [#152](id=78) made the userspace source at `2306c2e` authoritative; that source already lacked `overflow-checks = true`. The setting existed only in the prior full-kernel lineage from `9b11baea`, so it was not carried across the architecture transition. I found no rationale in PR [#152](id=79) saying release overflow checks were deliberately disabled or that all arithmetic had become explicitly checked.
The 65/65 result is useful evidence that restoring the setting does not break the unit suite, but the unreviewed `scan_layer` paths, self-start binaries, and release/runtime cost remain open. I am leaving this issue open for the maintainer decision. My recommendation is to restore `overflow-checks = true` as the safer default unless a release benchmark demonstrates a material cost that warrants a documented exception.
